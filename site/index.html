Can an agent find what drives a cancer outcome, and say nothing when nothing does?

ONC-AGI measures one analysis skill. Given a cohort of patients, their measurements and an outcome, can an agent name the measurements that drive the outcome rather than ones that merely travel with it? It must also avoid information that leaks from the outcome itself, recognise when there is nothing to find, and do all of this without buying more data than the question needs.

Why this task

Most proposed biomarkers never reach the clinic. A review of the biomarker pipeline describes a literature of “almost ubiquitous significant results” in which “few of these discovered biomarkers are used in routine clinical care”, and finds that discovery “suffers from poor methods and incomplete and selective reporting”1. Promising cancer biomarkers have repeatedly failed validation as false discoveries2.

The traps behind those failures are familiar to any analyst:

  • a correlate mistaken for a cause;
  • a confounder that lifts many measurements at once;
  • a variable measured after the outcome, which "predicts" it trivially;
  • a confident claim where the data support none.

An agent that avoids these traps on a real cohort would be useful to any group doing biomarker analysis. ONC-AGI turns each trap into a test you can score.

1 · A world is built from real patients

A world starts from real rows. Benchmark worlds draw patients without replacement from public cancer cohorts (TCGA-BRCA and SCAN-B), so the correlations between measurements are real: genes that move together still move together. This world has @@j-n@@ patients and @@j-features@@ measurements of several kinds.

One mechanism is planted. Here a single measurement, @@j-truth@@, drives the outcome. A second measurement, @@j-twin@@, is a near-duplicate of it. Correlated substitutes like this are common in real data, and the data alone may not be able to tell them apart.

An outcome is drawn from that mechanism, through a calibrated generator, at a fixed outcome rate. Which patients have the outcome now depends, noisily, on the planted measurement and on nothing else.

Then the traps are added. Three measurements are recorded after the outcome, and in some worlds one of them tracks it closely, as real follow-up data often does. Every name is replaced with a fake one, so knowing which genes matter in the literature cannot help.

2 · An oracle certifies what can be found

Before any agent plays, the world is replayed hundreds of times, with fresh patients and fresh outcomes each time, while the truth stays fixed. The oracle knows what was planted and asks whether it would show up. On these data it clears the bar reliably from about @@j-oracle-n80@@ patients. Its near-duplicate does too, and an unrelated measurement almost never does.

The bar is not a convention. It is the strongest association any measurement reaches by chance when there is no signal, simulated on this world's own data (here |z| = @@j-oracle-thr@@). A planted term is certified recoverable or neutral; anything in between is rebuilt. Because the data cannot separate the cause from its twin, both are accepted answers.

3 · The agent receives the world

The agent sees what an analyst would:

  • how many patients exist;
  • every measurement, with its kind and whether it was taken after the outcome;
  • the price of recruiting a patient and of each assay;
  • a budget.

It does not see the answer key, which never leaves the scorer. In this sequential mode, it sees no data until it pays for it.

4 · The agent buys data and analyses it

The agent here is deliberately simple. It recruits patients in batches, measures everything on them and tests each measurement against the outcome, with the usual correction for testing many at once.

After @@j-first-n@@ patients (@@j-first-spent@@ USD), one measurement already clears its line.

It buys more. With twice the patients the evidence sharpens, and the near-duplicate clears the line as well. The agent cannot know which of the two is the cause, and neither could a human analyst from these data alone.

With @@j-patients@@ patients its list is unchanged, so it stops and submits [@@j-submission@@]. It has spent @@j-spent@@ USD of a @@j-budget@@ USD budget. Knowing when you know enough is part of the task.

5 · The answer is scored

Scoring is deterministic code; no language model judges it. First, the two near-duplicates count as one answer, so listing correlated copies cannot inflate a score. Only the first R answers count, where R is the number of certified causes (here one).

The answer matches the key, because either twin is accepted. It is then compared with what a random list of the same kind would achieve, so lucky guessing scores zero on average.

Two checks follow. Listing any post-outcome measurement would have scored this world zero. Spending is compared with the oracle's reference study (@@j-ref@@ USD); this agent spent less, so its credit is not discounted.

The same scorer, run on other answers to the same world, shows what each rule is for. Equivalent answers earn credit. A leak costs everything. Silence costs Restraint. Listing everything is luck, not discovery.

6 · One world is an example; many make a score

The same agent played every public world, in both modes:

  • it solves single drivers, stand-ins, confounders and leaks;
  • it misses the interaction, where neither measurement matters alone;
  • it recovers only part of a module;
  • on worlds with no signal it correctly says nothing, but in sequential mode only after buying the whole cohort, which costs efficiency.

The headline combines finding with knowing when to stop: Discovery Score = Find × Restraint.

  • Find is chance-corrected recovery on worlds with a cause.
  • Restraint is how often the agent says nothing on worlds without one, minus how often it says nothing when there was something to find.

For this agent that is @@j-find@@ × @@j-restraint@@ = @@j-ds@@ (95% interval @@j-ds-low@@ to @@j-ds-high@@). Always answering, never answering, guessing and padding all score zero.

What it measures

Every world is one of a small set of published mechanisms. Each tests one part of an analyst's judgement, and each defeats a specific shortcut. The generator is private, as in ARC; the rules are not.

Analyst skillMechanismShortcut that fails
Find the driverGenerating: one to three measurements drive the outcome—
Accept what the data cannot distinguishStand-in: a near-duplicate of the driverInsisting on one exact measurement
Look across data typesWrong data type: a copy-number change drives the outcomeReading only gene expression
Separate cause from confoundingObserved confounder: a clinical subtype lifts many genesListing genes associated only through the subtype
Respect timeLeak: a post-outcome measurement tracks the outcomeRanking by association without reading timing
Reason about the unmeasuredHidden cause: an unmeasured driver with measured proxiesClaiming the proxy is the cause
Look for joint effectsInteraction, module, effect modifierMarginal screening; picking only the strongest member
Respect causal structureMediator, collider, Simpson's-paradox mixture, batch shiftTrusting associations created by selection, pooling or batch
Know when there is nothingNo signal: a twin of a real world with every effect removed (20% of worlds)Always naming something
Spend data wiselySequential mode: patients and assays cost moneyBuying everything before thinking

What a score means

  • The agent recovered planted mechanisms in real correlation structure, against an oracle certificate, more often than chance.
  • It said "nothing" when nothing was there, and paid for data in proportion to the question.
  • It did so without access to the answers: names are fake and the evaluation worlds are never reused.

Run your agent

The interface, the engine and the scorer are public. An agent receives a world card, chooses actions and submits a list. It runs offline through the same engine that scored the run above.

The 1.0.0rc3 world sets, 2,489 public-train worlds, are superseded and remain downloadable for reference. Eight of those worlds have answer keys that no solver can reach, and the release's first-pass results took the first worlds of each download, so every scored world came from one cohort source, METABRIC.

Needs Python 3.12 and uv. The smoke test takes about ten seconds.
